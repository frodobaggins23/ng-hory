# Create commit message

Propose commit message based on instructions below

DO look into git staging for changed files and propose a commit message based on the changes.

DO ignore changes that are not in git staging.

DO follow conventional commit principles

DO output only the commit mesage, no additional commentary is allowed.

DO keep the subject line under 50 characters

DO use present tense ("add" not "added")

DO start with capital letter.

DO NOT propose any commit message description.

DO NOT propose any attributions in the commit message.

DO NOT end the sentence with a dot.

DO NOT offer to commit. You MUST NOT commit changes, ever.



## Examples of good commit messages:

feat: Add calendar screen with holiday highlighting
docs: Document calendar service
refactor: Optimize pipes for date operations

## Examples of bad commit messages:

Add calendar screen with holiday highlighting
docs: document calendar service
refactor: Optimize pipes for date operations.
refactor: Optimize pipes for date operations that are used in calendar, table and other components in ng folder
